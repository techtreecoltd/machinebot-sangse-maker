# 하네스 보강과 상세페이지 제작 공수

산정일: 2026-09-21. 기준: [목표](harness-goals.md), [PRD](harness-prd.md). **작업 분해에 따른 계획 추정이며 실측·견적·납기 약속이 아니다.** 개발 공수와 개별 상품의 이미지 제작량을 구분한다.

## 1. 하네스 개발 공수

단위는 담당자 1명의 집중 작업 시간이다. 기존 1.9.0 지침을 재사용하고 별도 서버·UI·이미지 엔진은 만들지 않는다. 문서 작성, 구현, 관련 검증, 단계별 배포 정리를 포함한다. 승인·자료·생성 도구 대기 시간과 이미 끝낸 S0 설치·문서 작업은 제외한다. Codex의 실제 실행시간으로 환산하지 않는다.

| 단계 | 작업 분해 | 예상 공수 |
|---|---|---:|
| S1 · 현재 승인 | 질문·추천 기준 1~1.5h, 기존 경로 연결·문서 1~1.5h, 대화 회귀·패키지 2~3h | 4~6h |
| S2 | 누끼 독립화, 원본·검수 인계, 직접 실행과 실제 결과 확인 | 6~10h |
| S3 | 연출 독립화, 자산 활용·장면 기획, 실제 결과 검수 | 6~10h |
| S4 | 상세페이지·현지화 이전, 카피·구성 승인, 생성·회귀 검수 | 10~16h |
| S5 | 썸네일 분리, 메인·서브 경로와 검수 | 3~5h |
| S6 | 효용 시각화 분리, 주장 근거·효과 검수 | 4~7h |
| S7 | 전체 패키지 연결, 중복·재개·전체 회귀·완료 감사 | 6~10h |
| 합계 | S1~S7 직렬 진행 | **39~64h** |

하한에 20%, 상한에 30%의 재작업 예비 공수를 적용하면 `39 × 1.2 = 46.8h`, `64 × 1.3 = 83.2h`다. 작업 예약에는 올림한 **47~84h**, 1인일 8시간 기준 **약 6~10.5인일**을 사용한다. 이 예비율은 과거 실측에서 나온 값이 아닌 계획 가정이다.

상세페이지 스킬이 독립되는 S4까지는 S1~S4 합계 **26~42h**, 같은 예비율 적용 시 **32~55h**다. 모든 구현 단계에서 별도 설계 컨펌을 유지하며 이 합계가 S2 이후의 실행 승인을 뜻하지 않는다.

변동 요인은 실제 원본의 품질·옵션 구분, 새 스킬 간 자료 인계 오류, 한국어 문구 재생성, 검증 도구 가용성이다. 각 단계 완료 때 실제 작업 범위·수정 횟수·대기 시간을 분리해 기록하고 다음 단계 범위를 재산정한다.

## 2. 상품 하나의 상세페이지 제작량

기본 조건: 검수 가능한 제품 사진·확인된 정보가 있고, 상세페이지 구성과 카피를 승인받은 경우. 각 패널은 한 번의 호스트 호출에서 제품·장면·효과·카피를 함께 만든다. 첫 히어로를 스타일 테스트로 쓰면 별도 테스트 한 장을 추가 계산하지 않는다.

`총 호출 수 C = 상세 패널 N + 별도 납품 자산 A + 추가 생성 시도 R`

| 상세 장수 N | 별도 자산 없는 첫 생성 | 재시도가 N의 25~50%라는 가정의 추가 시도 | 예시 총 호출 |
|---|---:|---:|---:|
| 6장 | 6회 | 2~3회 | 8~9회 |
| 8장 | 8회 | 2~4회 | 10~12회 |
| 10장 | 10회 | 3~5회 | 13~15회 |

재시도 수는 `ceil(N × 가정 비율)`로 계산한 시나리오다. 실제 실패율이나 호출량 보장은 아니다. 한 패널에 여러 번 수정이 집중될 수 있고, 동일 오류 두 번 반복 시 기존 규칙에 따라 원인·대안을 확인한다.

누끼나 독립 연출컷도 함께 납품하도록 선택했을 때만 A에 더한다. 예를 들어 **누끼 2장 + 연출 4장 + 상세 8장 = 첫 생성 14회**다. 기존 자산을 재사용하면 새 호출이 생기지 않으며 같은 파일을 새 장면 수로 중복 계산하지 않는다. 상세페이지 안에 필요한 장면을 넣는 것만으로 독립 연출 세트 4회를 추가하지 않는다.

8장 제작의 사람 작업 예산 예시: 자료·소구 정리 20~40분, 구성·정확 카피 30~60분, 이미지 검수·수정 지시 30~60분, 파일 정리·납품 10~20분. 합계 **90~180분(1.5~3h)**이며 자료 부족·복잡한 표·새로운 콘셉트 탐색은 별도다. 이것 역시 실측 전 계획 가정이다.

직렬 작업의 전체 경과 시간은 `집중 작업 시간 + 각 생성 호출의 대기 시간 합 + 사용자 승인·자료 대기`로 산정한다. 호출당 지연과 호스트 요금·사용량은 이번에 측정하지 않았으므로 고정 시간이나 금액을 제시하지 않는다.

## 3. 승인 범위와 재산정 기준

- 2026-09-21 사용자는 “그런 범위로 진행”이라고 S1 범위를 승인했다. S1 구현·회귀·배포를 먼저 완료한다.
- S2 전에 누끼 입력과 공통 기록 형식의 실제 예시를 보여주고 확인받는다.
- 생성 재시도율은 최소 한 상품의 실제 결과·호출 내역을 확보한 뒤 추정값을 교체한다.
- 공수표는 예산을 설명한다. 작업이나 이미지가 실제로 완성됐다는 증거로 사용하지 않는다.
