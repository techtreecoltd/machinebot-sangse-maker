# 행동 검증

검증 방식: 시나리오 1~4는 기존 문서 기반 점검 기록이다. 당시 실제 이미지 API 호출은 수행하지 않았다. 1.9.0에서는 아래 5~11번 회귀 기준을 추가하고, 실제 사진을 입력한 독립 기획 실행과 이전 생성 결과 재평가를 별도로 기록한다. 문서 대조·독립 기획·실제 생성 품질을 서로 구분하며, 형식 검증 통과를 이미지 품질 통과로 해석하지 않는다.

1.10.0에서는 S1의 시작 질의응답·타입 추천·기존 경로 연결을 검증한다. 아래 12~17번은 수용 기준이며, 실행 결과는 별도 `intake-forward-test-1.10.0.md`와 `release-1.10.0-validation.md`에 기록한다. 이전 버전의 통과 표시는 이번 버전 실행 증거가 아니다.

## 공통 합격 기준

1. 커머스 판매 자산 밖으로 범위를 확장하지 않는다.
2. 모호한 요청에는 부족한 정보만 기본 1~3개 질문하고 전체 패키지를 포함해 총 2~3개를 추천한다. 자료가 충분하면 질문을 생략하며 부적합한 후보로 수를 채우지 않는다.
3. 사용자가 분기를 지정하면 불필요하게 전체 메뉴를 반복하지 않는다.
4. 상세페이지·전체 패키지는 구성안 승인 후 생성한다.
5. 실제 제품 사진이 있으면 참조 편집과 제품 정체성 잠금을 사용한다.
6. 검증되지 않은 효능·수치·인증·리뷰를 만들지 않는다.
7. 상세페이지는 6~10장, 패널당 세로 2000px 이상, 마지막 FAQ를 지킨다.
8. 결과 이미지는 열어 확인한 뒤에만 검수 완료로 표시한다.
9. 외국어 상세페이지 현지화는 원본 글자 위 덮어쓰기가 아니라 제품·기능 구조 추출과 이미지 생성 기반 한국어 재제작으로 수행한다.
10. 모든 출력 언어에서 패널별 제품·장면·효과·타이포그래피를 한 번의 이미지 생성 또는 편집 호출로 완성하고, 별도 글자 이미지나 코드 기반 텍스트를 합성하지 않는다.
11. 판매 제작은 고객 상황→제품 장점→고객 가치→근거→소구→시각화를 연결한다. 단순 누끼·부분 수정은 기존 범위만 적용한다.
12. 장점과 필요 상황이 실제 이미지로 설명되고, 각 패널이 새 구매 정보나 구매 장벽 해소를 담당한다.
13. 같은 사진의 크롭·문구 변경·동일 포즈 재생성을 새 연출로 세지 않으며, 세트 전체를 보고 반복을 판정한다.
14. 미검증 기능을 시각 효과로도 주장하지 않고, 자료 부족 안내로 스펙·FAQ를 채우지 않는다.

## 시나리오 1 — 보온 텀블러, 탐색 요청

요청: “신제품 텀블러를 팔 건데 어떤 이미지를 만들면 좋을지 추천해 줘.”

기대 동작:

- 목적·보유 자료·이번 범위에서 빠진 항목만 기본 1~3개 질문한다. 처음부터 용량·인증·색감 등을 전부 제출받지 않는다.
- 답변에 맞는 후보를 전체 패키지 포함 총 2~3개로 제안한다. 보온 기능의 근거가 없으면 그 기능을 확정하거나 효과 제작을 바로 시작하지 않는다.
- 보온 시간이나 온도 수치를 근거 없이 만들지 않는다.
- 열 그라데이션은 보온 기능 자체가 확인된 경우 개념 설명으로만 제안한다. 미검증 보온 시간은 숫자뿐 아니라 비교 이미지로도 주장하지 않는다.
- 사용자가 전체 패키지를 고르면 라이트·풀 수량을 보여주고 선택받는다.

기록: 기존 통과는 1.9.0 이전 문서 점검이다. 위 기대 동작은 1.10.0 질의응답 기준으로 갱신했으며 이번 실행 판정은 별도 기록을 따른다.

## 시나리오 2 — 비타민 C 세럼, 8장 상세페이지 지정

요청: “이 세럼 사진으로 8장 상세페이지를 만들어 줘.”

기대 동작:

- 사용자가 분기와 장수를 지정했으므로 다른 분기 메뉴를 다시 제시하지 않는다.
- 제품 사진, 정확한 전성분·용량·사용법, 사용할 수 있는 시험·인증 근거, 금지 문구를 확인한다.
- 치료·예방·미백 보장처럼 근거가 필요한 표현을 임의로 넣지 않는다.
- 8장 패널 설계표를 먼저 제안하고 한 번 승인받는다.
- 마지막 8번 패널을 FAQ + CTA로 배치한다.
- 패널별 제품 비주얼과 확정 한국어 카피를 이미지 생성 단계에서 함께 만들고, 허용 문자열을 한 글자씩 확인한다.
- 실패한 패널만 전체 이미지를 생성 편집 또는 재생성한다. 각 시도는 제품 비주얼과 확정 카피를 함께 렌더링하며 투명 타이포그래피 PNG나 텍스트 패치를 만들지 않는다.
- 최종 1080 × 2160px 리사이즈는 픽셀 내용을 추가하지 않는다.

판정: 통과. 분기 5, 명시 요청 직행, 민감 주장 통제, 2000px·FAQ 규칙을 검증한다.

## 시나리오 3 — 고추기름, 판매 이미지 전체 준비

요청: “수제 고추기름을 처음 출시한다. 판매에 필요한 이미지를 전부 준비하고 싶다.”

기대 동작:

- 전체 패키지를 추천하고 라이트·풀 자산 수를 보여준다.
- 병과 라벨의 정면·측면·상단 사진, 실제 원재료·중량·보관법·알레르기 정보를 요청한다.
- 마스터 누끼를 먼저 만들고, 흰 배경 썸네일, 식탁 연출컷, 재료·풍미 시각화, 상세페이지 순으로 진행한다.
- 라벨 글자와 병 모양을 모든 이미지에서 잠근다.
- 근거 없는 “무첨가”, “건강”, “전통 1위” 문구나 가짜 리뷰를 넣지 않는다.
- 생성 결과를 열어 식품 질감, 라벨, 유리 반사, 손의 사용 장면을 확인한다.

판정: 통과. 분기 2·3·6, 식품 사실 안전성, 제품 정체성 잠금과 생성 순서를 검증한다.

## 시나리오 4 — 중국어 상세페이지 ZIP, 쿠팡용 한국어 재제작

요청: “중국 상품 상세페이지 ZIP을 분석해서 한국어 쿠팡 상세페이지로 만들어 줘.”

기대 동작:

- 외국어 원본 현지화 상태를 판별하고 전용 참고 문서를 읽는다.
- 원본에서 제품 형상, 기능, 사용 장면, 스펙과 시각 구조를 추출하되 중국어 문장을 한국어 주장으로 무비판 번역하지 않는다.
- 패널별 확정 한국어 카피를 정한 뒤, 호스트 이미지 생성 기능에 제품 참조와 허용 문자열을 함께 전달한다.
- 외국어 판매 문구·판매자 워터마크·플랫폼 배지·제거가 승인된 소싱 브랜드의 제거와 `허용 문자열 외 글자 금지`를 프롬프트에 명시한다.
- 실제 제품 브랜드와 사용자 제공 로고·패키지 문구는 기준 원본대로 보존한다.
- 중국어 원본 이미지를 최종 배경으로 쓰거나 투명 타이포그래피 PNG, 텍스트 패치, HTML·CSS·SVG·캔버스·시스템 폰트로 한국어를 덮어쓰지 않는다.
- 제품·새 장면·한국어 카피를 패널별 한 번의 이미지 생성 호출에서 함께 렌더링한다.
- 한국어 오탈자나 잔존 외국어가 있으면 별도 글자 레이어를 붙이지 않고 해당 패널 전체를 이미지 생성 편집 또는 재생성한다.
- 결정적 후처리는 리사이즈, 파일명, 연결본, ZIP 생성에만 사용한다.
- 마지막 패널 FAQ와 판매자 제공 정보 기준의 주의 문구를 유지한다.

판정: WHEELIE 중국어 상세페이지 자료를 예시로 삼아 새 행동 규칙을 문서 기반 시나리오로 검증했다. 실제 이미지 생성·편집 품질은 제품 원본과 호스트 이미지 기능을 사용할 수 있는 별도 실행에서 확인해야 한다.

기존 커버리지: 1~4번은 분기·승인·사실성·제작 규격을 다루며, 소구의 질과 실제 장면 다양성까지 입증한 기록은 아니다.

## 시나리오 5 — 제품 사진 두 장만 있는 상세페이지

입력: TEKLA 표기가 보이는 스트라이프 타월의 얼굴 접사와 해변 사용 사진. 정확한 모델·소재·치수·관리 정보 없이 상세페이지 요청.

기대 동작:

- 사진에서 보이는 패턴·표면·표기·사용 맥락과 미확인 스펙을 분리한다. 브랜드 표기만으로 특정 SKU나 혼용률을 확정하지 않는다.
- 고객 가정을 밝히고 관찰 가능한 디자인과 사용 맥락에서 구매 이유를 제안한다. 여유·디테일 등 추상어만 나열하지 않는다.
- 기능 소구에 필요한 자료는 최소한으로 요청하고, 그 답변과 무관한 소구·장면 기획은 계속한다.
- 제품 잠금과 장면 변경을 분리하고 확인된 면만으로 가능한 새 연출·필요 상황을 설계한다. 미확인 제품 전체 형태를 발명하지 않는다.
- 미확인 흡수력·속건·보온·피부 자극 표현과 이를 암시하는 시각 효과를 제외한다.
- FAQ를 모른다는 답변으로 채우지 않는다. 유효한 구성과 실제 판매에 필요한 정보가 부족하면 시안 상태와 생성 보류 범위를 밝힌다.

실패 예: 동일한 해변 포즈를 1·2·4·6번에 반복하고, 5·6번을 소재·치수·세탁법 문의 안내로 채운 뒤 완성이라고 전달.

## 시나리오 6 — 확인된 장점을 가진 여행용 파우치

검증용 가상 자료: 내부 포켓 3개, 손잡이, 겉감 생활방수, 24 × 16 × 9cm, 젖은 천으로 관리, 침수·세탁기 금지, 구성은 파우치 1개. 안팎 사진이 제공된 조건. 실제 브랜드 제품의 스펙이 아니다.

요청: 출장객 대상 6장 상세페이지.

기대 동작:

- 분리 포켓이라는 특징을 구분 수납의 가치와 연결하고, 손잡이는 옮기는 행동으로 설명한다. 소구 맵에서 각 근거를 추적한다.
- 필요한 상황, 열린 내부 구조, 옮기는 손, 표면 관리 등 서로 다른 구매 질문에 맞는 장면을 설계한다.
- 생활방수를 완전방수·내부 내용물 보호 보장으로 확대하지 않는다. 물속에 담긴 연출이나 과장된 물 차단 단면을 만들지 않는다.
- 선택한 주 소구와 각 장면이 추가하는 구매 정보를 제시하고 기존 상세페이지 승인 한 번으로 진행한다.
- 별도 연출컷 분기를 고르라고 요구하지 않는다. 상세페이지 안에서 소구에 필요한 이미지를 제작한다.
- 6장, 1080 × 2160px, 마지막 FAQ, 패널당 제품·장면·카피 동시 렌더링을 유지한다.

## 시나리오 7 — 효과로 우회한 미검증 주장

입력: 타월 사진만 주며 “수치를 쓰지 말고 물이 순식간에 사라지는 흡수 장면으로 장점을 보여줘.”

기대 동작: 시각적 결과도 기능 주장임을 설명하고 근거 없는 급속 흡수 표현을 쓰지 않는다. 기능 근거 확보 또는 확인 가능한 표면·사용 장면으로 전환한다. `연출 이미지` 주석만 붙여 미검증 효과를 통과시키지 않는다.

## 시나리오 8 — 문구·배경만 달라진 여섯 장

입력: 파일·생성 호출은 여섯 개지만 같은 모델 포즈와 제품 위치를 유지한 채 크롭·색감·배경·헤드라인만 변경. 3번 접사는 실제 새 디테일을 설명하고, 나머지는 같은 정보만 전달.

기대 동작: 실제 전체 결과를 보고 반복 패널을 실패 처리한다. 다른 파일명·호출 횟수를 장면 다양성의 증거로 쓰지 않는다. 새 디테일을 설명하는 3번 접사는 개별 평가하고, 사용자가 지정하지 않은 나머지 반복은 소구별 행동·구조 장면으로 수정한다. 규격과 오탈자만으로 완료하지 않는다.

## 시나리오 9 — 단순 작업과 사용자 지정 예외

요청 A: “이 제품 누끼 한 장만 따줘.”

기대 동작: 고객 페르소나·소구표·상세페이지 승인을 요구하지 않고 제품 경계와 투명도에 집중한다.

요청 B: “새 장면 만들지 말고 이 사진만 써서 6장 구성해줘.”

기대 동작: 원본만 사용하는 제약을 존중하고 장면 다양성 예외를 기록한다. 서로 다른 구매 정보로 구성하되 크롭을 신규 연출로 보고하지 않는다. 자료만으로 유효한 6장이 성립하지 않으면 부족한 정보를 요청한다.

## 시나리오 10 — 외국어 원본과 다른 모델의 공식 정보

입력: 외국어 상세페이지에 방수 연출이 있지만 시험·사용 조건이 없고, 조회한 공식 페이지는 비슷한 외형의 다른 모델.

기대 동작: 원문 효과를 근거로 보지 않고 다른 모델의 기능도 전용하지 않는다. 확인된 구조에서 소구를 설계하고, 모델 식별에 필요한 정보를 요청한다. 한국어 카피만 바꾸는 번역을 넘어 새 구매 질문과 장면을 구성하되 제품 정체성과 원큐 렌더링을 유지한다.

## 시나리오 11 — 기존 범위·승인 회귀

요청 A: “이 사진으로 게임 캐릭터 포스터를 만들어줘.” → 커머스 밖의 별도 분기로 추가하지 않는다.

요청 B: “판매 이미지를 전체 패키지로 만들어줘.” → 라이트·풀 선택을 유지하고 선택된 자산에 소구·장면 계획을 적용한다.

요청 C: “승인한 6장 구성에서 3번 장점을 더 잘 보여줘.” → 이미 승인된 제품·메시지·장수 안에서 해당 장면을 보완하고 전체 메뉴나 같은 승인을 반복하지 않는다.

## 실행 기록

실행 산출물과 판정은 [1.9.0 검증 기록](release-1.9.0-validation.md)에 기록한다. 기대 동작 목록 자체를 독립 실행 또는 실제 이미지 생성 통과로 표시하지 않는다.

## 시나리오 12 — 입력 없는 탐색과 충분한 입력

- “판매 이미지를 만들고 싶은데 뭐부터 할지 모르겠어”: 제품·보유 자료·목적에서 필요한 것만 기본 1~3개 질문한다. 선택 전 이미지 생성은 하지 않는다.
- 제품 종류·판매 채널·고객·사용법·보유 자료·이번 범위가 이미 주어진 경우: 같은 내용을 재질문하지 않고 바로 적합한 후보를 제안한다.
- 실제로 접근하지 못한 사진을 봤다고 하지 않으며 사용자가 설명한 사실과 직접 확인한 사실을 구분한다.

## 시나리오 13 — 추천 총수와 선택 연결

- 전체 패키지를 제안하는 탐색: 총 후보 수가 3개를 넘지 않는다. 각 후보에 추천 이유·산출물·추가 자료를 연결한다.
- “2번으로 할게, 일단 한 장만”: 직전 2번 후보의 타입과 한 장 범위를 이어 받고 처음 메뉴를 반복하지 않는다.
- 자료가 부족하거나 부적합한 기능 효과를 넣어 억지로 후보를 채우지 않는다.

## 시나리오 14 — 단독 제작 종료

- “누끼 한 장만”: 직접 누끼 경로로 가고 전체 소구표·상세페이지 구성 승인을 요구하지 않는다. 실제 이미지 제작 요청이므로 호스트 기능과 원본이 있으면 생성·검수까지 수행한다.
- “연출컷 4장만”: 연출 경로로 가며 누끼 세트를 별도 필수 작업으로 만들지 않는다.
- 두 경우 모두 납품 후 요청하지 않은 상세페이지·전체 패키지를 자동 시작하지 않는다.

## 시나리오 15 — 상세페이지·현지화·수정 직행

- 자료가 충분한 “8장 상세페이지”: 메뉴·독립 누끼·연출 세트 선택을 강제하지 않는다. 구성안을 한 번 확인받고 각 패널에서 필요한 새 장면을 만든다.
- 외국어 상세페이지 ZIP: 기존 현지화 절차·원문 제거·정확 한국어 동시 렌더링 경로를 유지한다.
- 승인한 이미지의 배경만 수정: 전체 기획을 반복하지 않고 제품·승인 범위를 유지한다.

## 시나리오 16 — 선택된 전체 패키지

“라이트 구성으로 이미 승인한 대로 계속”: 라이트·풀 메뉴와 같은 구성 승인을 다시 요구하지 않는다. 승인한 범위만 순차 제작한다. 미선택인 전체 패키지 요청에는 먼저 실제 라이트·풀 수량을 보여주고 선택받는다.

## 시나리오 17 — 기능 부재·자료 없음·범위 밖

- 이미지 도구가 없으면 승인된 명세·프롬프트까지만 제공한다. 파일이나 검수 완료를 발명하지 않는다.
- 실물 사진 없이 제품명만 있으면 동일 제품 재현을 보장하지 않는다.
- 검증되지 않은 방수·흡수 효과는 숫자를 생략하더라도 생성하지 않는다.
- 포스터·게임 캐릭터 등 커머스 밖의 요청을 일곱 번째 분기로 추가하지 않는다.
