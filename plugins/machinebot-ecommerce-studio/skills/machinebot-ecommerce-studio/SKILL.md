# 김머신 이커머스 상세페이지 스튜디오

제품 자료에서 고객이 구매할 이유를 찾고, 근거 있는 소구와 이를 보여줄 장면을 설계해 선택한 커머스 이미지를 완성한다. 사용자 언어로 응답하며 한국어 요청에는 한국어를 기본으로 쓴다.

## 범위

이 스킬은 판매 페이지에 필요한 다음 여섯 가지 결과물만 다룬다.

1. 메인·서브 썸네일
2. 누끼컷
3. 연출·실사용컷
4. 효용·기능 시각화컷
5. 6~10장 상세페이지 이미지
6. 위 자산을 묶은 전체 이미지 패키지

포스터, 캐릭터, 게임, 순수 일러스트, UI 디자인처럼 상품 판매 자산이 아닌 범용 이미지 작업으로 확장하지 않는다.

## 반드시 지킬 것

- 사용자가 준 제품 사진, 로고, 패키지 문구와 사실 정보를 기준 원본으로 취급한다.
- 효능, 인증, 수치, 원산지, 순위, 리뷰, 비교 우위, 의학·건강 주장을 추측하거나 만들어내지 않는다.
- 사용자가 원하는 분기를 이미 명확히 지정했다면 전체 메뉴를 다시 강요하지 않는다.
- 탐색 요청에는 부족한 정보만 기본 1~3개 질문한 뒤, 전체 패키지를 포함해 총 2~3개 타입을 이유와 함께 제안한다. 이미 자료가 충분하면 질문을 생략하고, 부적합한 후보로 개수를 채우지 않는다.
- 단순 분기는 사용자의 분기 선택을 제작 승인으로 본다. 상세페이지와 전체 패키지는 패널 구성안을 한 번 승인받은 뒤 이미지 생성에 들어간다.
- 상세페이지·썸네일 등 글자가 포함된 각 최종 자산은 제품, 장면, 효과, 확정 카피를 한 번의 이미지 생성 또는 편집 호출 안에서 함께 렌더링한 평탄화 이미지여야 한다. 텍스트 없는 베이스와 별도 글자 레이어를 만들지 않는다.
- 투명 타이포그래피 PNG, 텍스트 패치, HTML·CSS·SVG·캔버스·시스템 폰트로 글자를 만든 뒤 합성하는 경로는 사용자 언어와 무관하게 금지한다.
- 이미지 생성 도구가 없는 환경에서는 생성했다고 말하지 않는다. 승인된 이미지 프롬프트와 제작 명세를 제공하고 제한을 밝힌다.
- 결과 이미지를 직접 확인하지 못했다면 완성·검수됐다고 말하지 않는다.
- 판매 목적의 신규 제작은 소구 맵과 장면 설계를 먼저 연결한다. 제품 장점과 필요 상황을 실제 이미지로 보여주고, 같은 사진·포즈의 반복으로 장수를 채우지 않는다.

## 작업 흐름

### 1. 시작 상태 판별

다음 중 현재 상태를 먼저 정한다.

- `탐색`: 사용자가 무엇을 만들지 아직 모른다.
- `분기 지정`: 썸네일, 누끼, 연출컷, 효용 시각화, 상세페이지, 전체 패키지 중 하나를 요청했다.
- `수정`: 기존 판매 이미지 또는 상세페이지를 고치려 한다.
- `외국어 원본 현지화`: 중국어·일본어 등 외국어 상세페이지, ZIP, 스크린샷 또는 상품 이미지를 한국형 상세페이지로 재제작하려 한다.

[시작 질의응답과 연결](references/intake-routing.md)을 읽고 현재 상태에 맞는 경로를 고른다. 탐색이면 목적·보유 자료·이번 범위에서 부족한 정보만 확인한 뒤 [제작 분기](references/branches.md)로 추천한다. 분기가 지정됐으면 해당 분기만 읽고 바로 필요한 입력을 확인한다. 단독 작업을 상세페이지나 전체 패키지로 자동 확장하지 않는다.
외국어 원본 현지화이면 [외국어 상세페이지 현지화](references/source-detail-localization.md)를 반드시 읽고, 원문의 제품·기능 구조를 분석한 뒤 해당 절차로 직행한다.
단순 누끼·배경 제거·오탈자 수정은 기존 목적을 유지한다. 썸네일 세트·연출·효용 시각화·상세페이지·전체 패키지를 새로 기획하거나 설득력을 고칠 때는 분기와 관계없이 [소구 설계와 장점 시각화](references/sales-visual-strategy.md)를 읽는다. 현지화에도 같은 소구·장면 기준을 적용한다.

### 2. 최소 입력 수집

이미 제공된 내용과 접근 가능한 자료를 먼저 확인한다. 탐색 중에는 제작 타입 선택을 바꾸는 질문만 기본 1~3개씩 묻는다. 제품명·자료·목적이 이미 있으면 재질문하지 않는다. 자료가 너무 적어 적합성을 판단할 수 없으면 필요한 답을 기다리며, 추천·선택 전에 이미지를 생성하지 않는다.

분기가 선택되거나 명시됐으면 아래에서 그 제작에 꼭 필요한 정보만 확인한다. 이 목록 전체를 공통 필수 설문으로 사용하지 않는다. 단순 누끼에는 제품 사진과 출력 조건만 확인하고, 상세페이지용 고객·전체 스펙·소구표를 요구하지 않는다.

- 제품명·카테고리와 판매 대상
- 정면·측면·패키지 등 제품 사진, 로고, 브랜드 자료
- 검증된 특징·스펙·사용법·주의사항·인증 근거
- 핵심 고객과 사용 상황
- 판매 채널과 필요한 비율·파일 규격
- 선호·금지 색감, 참고 이미지, 반드시 넣을 정확한 문구

실물 사진이 없으면 콘셉트 시안은 만들 수 있지만 실제 제품과 동일하다고 보장할 수 없음을 먼저 알린다. 보이지 않는 뒷면·내부·부속을 임의로 만들어내지 않는다.
자료 부족 시 보유 자료와 정확한 모델의 확인 가능한 공식 근거를 먼저 활용하고, 제작을 좌우하는 항목만 묶어 질문한다. 미확인 사실은 내부 확인 목록에 두며, 소비자용 패널을 `정보 없음·판매자에게 문의`로 채우지 않는다. 근거 있는 소구만으로 성립하는 기획은 계속 진행하되 판매 필수 정보가 빠진 결과는 시안으로 구분한다.

### 3. 제품 진단과 분기 제안

다음 세 층으로 자료를 정리한다.

- `확정 사실`: 사용자가 제공했거나 근거가 있는 정보
- `확인 필요`: 해당 주장·장면에 사용하기 전에 근거를 확보해야 하는 정보
- `연출 선택`: 분위기, 배경, 소품, 카메라, 시각 효과처럼 창작 가능한 요소

탐색 요청에는 전체 패키지를 포함해 총 2~3개를 다음 형식으로 제안한다. 권할 수 있는 후보가 하나뿐이면 이유를 밝히고 억지로 늘리지 않는다. 명시 요청에는 이 추천 메뉴를 생략한다.

1. `추천 분기 — 추천 이유`
2. 예상 산출물 수와 핵심 장면
3. 시작에 필요한 추가 자료

가장 적합한 하나에는 `추천`을 표시한다. 사용자가 선택하면 [연결 브리프](references/intake-routing.md)의 항목으로 선택 범위·기존 자료·미확인 사항을 짧게 정리하고 이 스킬의 해당 제작 절차로 진행한다. 누끼는 [독립 누끼 스킬](../machinebot-product-cutout/SKILL.md)을 읽고 실행한다. 연출은 [독립 연출 스킬](../machinebot-lifestyle/SKILL.md)을 읽고 실행한다. 나머지 분기는 이 스킬의 제작 절차를 따른다. 선택을 이미 했다면 다시 메뉴를 고르게 하지 않는다.

### 4. 소구·시각화 설계와 브리프 확정

누끼 요청은 [machinebot-product-cutout](../machinebot-product-cutout/SKILL.md)으로 연결하고 [제품 기록](references/product-context.md)을 이어 쓴다. 연출·실사용은 [machinebot-lifestyle](../machinebot-lifestyle/SKILL.md)로 연결한다. 독립 스킬의 절차를 중복 실행하지 않는다.

단순 누끼·배경 제거·오탈자 수정은 제품 기준과 요청 범위를 유지해 5단계의 해당 편집으로 진행한다. 전체 소구 설계를 새로 요구하지 않는다.

선택한 분기의 목표, 대상 고객, 사용 상황과 구매 장벽을 정한다. [소구 설계와 장점 시각화](references/sales-visual-strategy.md)에 따라 `제품 특징·장점 → 기능적·감성적 고객 가치 → 근거 → 핵심 메시지 → 보여줄 행동·상태`를 연결한 소구 맵을 만든다. 주 소구와 필요한 보조 소구를 고른 뒤 장면 설계표에 연결한다. 예쁜 배경·추상적 감성 문구만으로 이 단계를 통과하지 않는다.

각 장면은 제품 장점이나 필요 상황을 이해시켜야 한다. 제품 참조는 정체성을 유지하는 기준이며 배경·포즈를 복제하라는 지시가 아니다. 새 연출·사용 장면·기능 시각화 중 소구에 맞는 방식을 고르고, 미검증 기능은 시각 효과로도 주장하지 않는다. 상세페이지 안에 필요한 연출과 시각화를 포함하며 별도 분기 선택을 요구하지 않는다.

보존할 제품 요소, 스타일, 비율, 산출물 수를 요약한다. 호출량이 크게 늘 수 있는 전체 패키지는 `라이트`와 `풀` 범위를 제안하고 사용자가 택하게 한다.

상세페이지 또는 전체 패키지라면 [상세페이지 설계](references/detail-page-blueprint.md)를 읽고 6·8·10장 중 적절한 구성을 제안한다. 핵심 소구와 패널별 구매 질문·헤드라인·시각화·근거·새 구매 정보를 보여준 뒤 한 번 승인받는다. 이미 승인한 범위 안의 품질 보완에 재승인을 요구하지 않는다.

### 5. 이미지 생성과 편집

실제 생성·편집을 시작할 때 [이미지 제작](references/image-production.md)을 읽고 호스트가 제공하는 이미지 생성 기능을 사용한다.

- 제품 정체성이 중요하면 사용자 제품 사진을 참조한 편집을 우선하되, 장면 설계표에 맞춰 새 사용 상황·배경·구도를 만든다. 제품 잠금과 장면 변경 지시를 분리한다.
- 가장 정확한 원본을 제품 기준으로 고정한다. 필요할 때만 마스터 누끼를 만들며, 상세페이지의 첫 납품 히어로를 스타일 테스트로 사용할 수 있다. 그 방향을 확인한 다음 나머지 자산을 만든다.
- 여러 패널을 한 이미지 호출에 몰아넣지 않는다. 패널 또는 자산 역할별로 생성하되, 한 패널의 제품·배경·효과·타이포그래피는 한 번의 호출에서 모두 완성한다.
- 외국어 상세페이지 현지화에서는 원본 이미지를 최종 배경으로 재사용하거나 새 언어를 덮어쓰지 않는다. 제품·기능·구도 정보만 추출하고, 한 번의 이미지 생성 호출에서 원문 제거와 확정 한국어 카피 렌더링을 함께 수행한다.
- 일반 제작과 외국어 현지화 모두 오탈자·잔존 외국어·가짜 글자가 있으면 별도 글자 이미지를 붙이지 않고 해당 패널 전체를 이미지 생성 편집하거나 재생성한다. 각 재시도도 최종 평탄화 이미지 한 장을 직접 만든다.
- 정확 문자열이 두 번 연속 실패하면 문구 축약이나 페이지 간 정보 재배치를 사용자에게 제안한다. 정확성이 필수인 법정 고지·성분표를 호스트가 렌더링하지 못하면 완료라고 하지 말고 제한을 밝힌다.
- 결정적 도구는 패널 리사이즈, 파일명 정리, 세로 연결, ZIP 패키징처럼 글자를 새로 그리지 않는 후처리에 사용한다.
- 생성 후 각 이미지를 열어 제품 형상, 로고·패키지, 손·사용 장면, 오탈자, 색감, 여백과 소구의 시각적 전달을 확인한다. 결과가 원본 구도로 돌아가거나 장점을 설명하지 못하면 해당 패널을 수정한다.

### 6. 검수와 전달

최종 전달 전에 [품질 게이트](references/quality-gates.md)를 읽고 해당 분기 항목을 확인한다. 실패한 자산만 목표 수정한다. 같은 문제가 두 번 반복되면 무작정 재생성하지 말고 제약과 가능한 대안을 사용자에게 알린다.
개별 패널뿐 아니라 전체를 나란히 보며 장면·메시지 반복을 확인한다. 소구·시각화·정보 진전이 실패하면 파일 크기와 오탈자가 통과해도 완성으로 표시하지 않는다. 소구 ID와 실제 결과 파일을 연결한 검수 기록을 남긴다.

전달 시 다음을 포함한다.

- 생성된 이미지 또는 다운로드 가능한 파일
- 번호·용도·픽셀 크기·비율을 담은 간단한 산출물 목록
- 사용자가 확인해야 할 미검증 문구나 사실
- 수정이 필요할 때 지정할 수 있는 이미지 번호와 수정 범위

단독 제작은 선택한 결과물을 전달한 뒤 끝낸다. 다음 작업을 제안할 수 있지만 요청하지 않은 연출·상세페이지를 자동 생성하지 않는다. 전체 패키지로 승인된 범위는 해당 자산을 순차 제작하며 스킬 전환을 이유로 같은 선택·승인을 반복하지 않는다.

## 기본 시각 원칙

- 메인 상품컷은 별도 요청이 없으면 중성 흰색 스튜디오 베이스, 정확한 화이트 밸런스, 깨끗한 그림자를 사용한다.
- 누런 캐스트와 과도한 주황색 조명, 플라스틱 같은 CGI 광택, 제품을 가리는 무관한 소품을 피한다.
- 연출·실사용컷은 제품과 고객 상황에 맞을 때 배경색과 조명을 확장할 수 있다.
- 열, 냉기, 공기 흐름, 흡수, 탄력 같은 보이지 않는 효용은 시각적 은유로 표현하되 측정 결과처럼 오해시키지 않는다.
- 사용자의 명시적 브랜드 가이드와 요구가 이 기본값보다 우선한다.
