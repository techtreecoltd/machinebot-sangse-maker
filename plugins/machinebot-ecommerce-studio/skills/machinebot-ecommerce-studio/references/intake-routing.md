# 시작 질의응답과 제작 연결

사용자가 무엇을 만들지 결정하도록 돕고, 선택한 범위의 기존 제작 절차에 연결한다. 누끼는 [독립 스킬](../../machinebot-product-cutout/SKILL.md)로 실행하며 연출은 [독립 연출 스킬](../../machinebot-lifestyle/SKILL.md), 상세페이지·현지화는 [독립 상세페이지](../../machinebot-detail-page/SKILL.md), 썸네일은 [독립 썸네일](../../machinebot-thumbnail/SKILL.md), 효용은 [독립 효용](../../machinebot-benefit-visual/SKILL.md), 전체 패키지는 [패키지 연결](package-orchestration.md), 나머지는 상위 `SKILL.md`를 따른다. [제품 기록](product-context.md)을 작업 간 이어 쓴다.

새 세션의 사용법 안내와 명시 요청은 [시작 안내](start-here.md)를 먼저 적용한다. 분기 선택은 납품 범위만 정한다. 모델·효용·흰 배경·문구 등 표현은 제공 자료와 구매 질문으로 별도 선택하며 썸네일 한 장도 생략하지 않는다.

## 1. 진입 판별

| 사용자 상태 | 다음 행동 |
|---|---|
| “무엇부터?”, “판매 이미지 준비”, 목적이 불명확함 | 이미 받은 정보를 확인하고 부족한 항목만 질문 |
| “누끼 한 장”, “연출 4장”, “8장 상세페이지” | 해당 분기 직행. 전체 메뉴 생략 |
| “전체 패키지”, “전부 준비” | 전체 패키지 직행. 아직 안 정했다면 라이트/풀 범위 확인 |
| “이 이미지 배경만”, “3번 문구 수정” | 기존 목적·승인 범위를 유지한 부분 수정 |
| 외국어 상세페이지·ZIP을 한국어로 재제작 | `source-detail-localization.md` 분석 경로 직행 |
| 범용 포스터·게임·캐릭터 등 | 커머스 범위를 설명. 새 분기로 추가하지 않음 |

선택한 타입·수량·원본이 명확하면 이미 얻은 답을 다시 묻지 않는다. 후속 “2번으로”, “그럼 누끼부터”도 바로 직전 추천과 연결한다. 참조할 추천이 여러 개여서 대상이 불명확할 때만 짧게 확인한다.

## 2. 최소 질문

다음 세 축에서 **추천을 바꿀 미확인 항목만** 기본 1~3개 질문한다. 체크리스트를 전부 제출받는 절차가 아니다. 질문에 답하지 않아도 이미 충분한 정보가 있으면 그것으로 판단하고, 필요한 결정이 빠졌다면 답을 기다린다.

| 축 | 필요한 경우의 질문 예시 |
|---|---|
| 목적 | 지금 가장 필요한 건 상품 등록용 사진, 사용하는 장면, 상세페이지 중 어느 쪽인가요? 아직 모르셔도 됩니다. |
| 제품·자료 | 어떤 제품이며, 원본 사진·누끼·기존 상세페이지 중 가지고 있는 자료가 있나요? |
| 이번 범위 | 필요한 이미지부터 준비할까요, 판매 이미지 전체가 필요할까요? |

이미 첨부한 자료는 직접 확인할 수 있으면 먼저 읽는다. 열 수 없으면 해당 자료의 접근·재첨부만 요청하고 확인했다고 주장하지 않는다. 고객·판매 채널은 추천을 바꿀 때만 보충하고, 색감·규격·정확 문구는 선택한 제작에서 필요한 때 확인한다.

첫 응답 예시 — 제품·자료가 전혀 없는 요청:

> 어떤 제품을 판매하시고, 가지고 있는 제품 사진이나 기존 상세페이지가 있나요? 당장 필요한 결과를 모르시면 자료를 보고 먼저 준비할 이미지부터 추천하겠습니다.

답변·자료가 충분하면 이 질문을 반복하지 않는다. 실물 사진이 없으면 실제 제품과 같은 이미지를 만들 수 있다고 보장하지 않는다. 제품명을 보고 보이지 않는 형상·로고를 상상해 기준컷으로 고정하지 않는다.

## 3. 추천 판단과 표시

수량은 [제작 분기](branches.md)를 기준으로 한다. 다음 표는 판단 근거이며 고정 추천 메뉴가 아니다.

| 현재 상황 | 우선 검토할 타입 | 추천 시 확인할 제한 |
|---|---|---|
| 제품 전체는 보이지만 배경이 복잡하고 기준컷이 없음 | 누끼컷 | 가려진 부품·미제공 각도는 복원하지 않음 |
| 제품 사진이 충분하고 목록용 이미지가 필요함 | 메인·서브 썸네일 | 채널 규격을 확인하지 않고 준수한다고 단정하지 않음 |
| 제품 사용 모습·공간을 보여주고 싶음 | 연출·실사용컷 | 실제 사용법·크기·확인된 면에 맞는 장면 |
| 확인된 기능·구조를 설명할 필요가 있음 | 효용·기능 시각화컷 | 기능의 근거가 먼저. 숫자가 없어도 효과는 주장이 될 수 있음 |
| 구매 설명과 정확한 카피·구성이 필요함 | 상세페이지 | 필요한 사실과 마지막 FAQ가 성립하는지 확인 |
| 신규 출시로 여러 판매 자산이 필요함 | 전체 패키지 | 라이트/풀 수량과 구성 선택·승인 |

전체 패키지 포함 **총 2~3개**, 가장 적합한 하나에 `추천`을 표시한다. 권할 수 있는 타입이 하나뿐이면 이유를 설명하고 그 범위만 제안한다. 관련 없는 세 번째 후보나 네 번째 전체 패키지를 자동으로 덧붙이지 않는다.

각 후보에는 `타입 — 현재 자료·목적과 연결한 이유 / 예상 수량·종류 / 필요한 추가 자료`를 표시한다. 추가 자료가 없다면 없다고 간단히 적는다. 스타일이나 분위기 대신 사용자가 받을 결과물 타입을 먼저 선택하게 한다.

예시 — 상품은 식별 가능하고 사용법도 확인됐지만 등록용 사진이 없는 경우:

> 1. **누끼컷 — 추천:** 흰색 스튜디오 배경과 전문적인 조명·접지 그림자를 갖춘 제품 기준컷입니다. 정면·3/4·측면·상부 등 원본에서 확인 가능한 각도를 1~4장 구성합니다.
> 2. **메인·서브 썸네일:** 상품 등록이 급하다면 메인 1장+서브 5~7장으로 구성합니다. 사용할 판매 채널을 알려주시면 규격 확인에 반영하겠습니다.

탐색 단계의 추천은 제작 시작이 아니다. 사용자가 고른 범위를 확인한 뒤 필요한 제작 입력을 보완한다. 이미 분기를 지정한 사용자는 이 메뉴를 거치지 않는다.

## 4. 선택한 범위 연결

기존 대화에서 다음 내용을 짧게 이어 쓴다. 내부 제작 브리프이므로 빈 양식을 사용자에게 새로 작성시키지 않고, 값이 없는 항목은 해당 제작을 좌우할 때만 질문한다. 자료와 검수 자산은 [제품 기록](product-context.md)의 product-context.json에 이어 쓴다. 파일 도구가 없으면 대화로 인계하고 저장했다고 말하지 않는다.

| 항목 | 연결할 내용 |
|---|---|
| 요청 범위 | 타입·수량·용도, 단독 또는 전체 패키지 |
| 기존 자료 | 제품·스타일·브랜드 원본과 이미 제공된 정보 |
| 제품 기준 | 보존할 형상·색·로고, 확인되지 않은 면·부위 |
| 사실 경계 | 확인 사실과 근거, 해당 작업에 필요한 확인 사항 |
| 제약·승인 | 정확 문구·금지 요소, 선택된 범위와 실제 구성 승인 여부 |
| 다음 행동 | 필요한 질문, 제작 기획, 구성 승인 또는 생성·편집 중 현재 할 일 |

브리프 예시: `누끼 1장 / 첨부 정면 사진 / 라벨·형상·색상 보존 / 흰색 스튜디오·중성 조명·접지 그림자 / 분기 선택됨 / 생성·검수 후 종료`. 고객 페르소나·상세 카피는 이 작업의 필수 입력이 아니다.

- 누끼·썸네일·연출·효용 등 단순 분기는 사용자의 구체적인 요청·선택이 제작 승인이다. 필요한 입력을 확보하면 해당 절차를 실행한다.
- 상세페이지는 패널 구성안을 한 번 승인받는다. 자료가 충분하면 별도 누끼·연출 세트 생성을 강제하지 않고, 필요한 새 장면을 각 상세 패널 안에서 만든다.
- 전체 패키지는 이미 선택한 라이트/풀과 승인 범위를 유지한다. 미선택일 때 수량과 범위를 보여주고 고르게 한 다음, 구성안을 확인받아 순차 실행한다. 선택과 구성 승인을 한 응답에 함께 받았으면 되풀이하지 않는다.
- 부분 수정은 요청한 영역만 수정하고 기존 범위의 승인·제품 기준을 유지한다.
- 후속 요청은 기존 자료와 검수 상태를 이어 받는다. 원본이 사라졌거나 제품 옵션이 다르면 확인 후 사용한다.

## 5. 종료와 제약

생성·검수 절차는 상위 `SKILL.md`의 4~6단계와 해당 참조를 따른다. 단순 누끼·부분 수정은 전체 소구 기획을 생략한다. 이미지 도구가 없으면 제작 명세까지만 제공하고 실제 생성 완료로 표시하지 않는다. 결과를 열지 못하면 검수 완료로 표시하지 않는다.

단독 요청은 그 결과물의 전달로 종료한다. 다음 타입을 제안할 수 있지만 선택받지 않은 이미지를 추가 생성하지 않는다. 전체 패키지로 이미 승인된 작업만 그 범위 안에서 다음 자산으로 이어 간다.
