# 소구 설계와 장점 시각화

메인 한 장을 포함한 썸네일, 연출·실사용컷, 효용 시각화, 상세페이지, 전체 패키지의 기획 전에 읽는다. 단순 누끼·배경 제거·오탈자 수정은 기존 목적을 유지하고 이 기획을 새로 요구하지 않는다. 외국어 원본도 번역 전에 같은 절차를 적용한다.

## 1. 근거에서 구매 이유까지

먼저 핵심 고객, 사용 순간, 해결할 불편 또는 얻고 싶은 경험, 구매를 망설이는 이유를 짧게 정한다. 사용자 자료로 확인되지 않은 고객 가설은 기획 가정으로 표시한다. 고객이 실제로 말했다는 가짜 인터뷰나 후기를 만들지 않는다.

제품 특징을 나열한 뒤 각각 `특징 → 실제 사용에서 달라지는 점 → 고객이 얻는 가치 → 이를 보여줄 장면`으로 연결한다. 기능적 가치와 감성적 가치를 모두 검토하되 근거 없는 기능을 개수 맞추기용으로 만들지 않는다. 일반적인 카테고리 용도와 이 제품만의 장점을 구별한다.

확인된 구조에서 직접 설명할 수 있는 사용상 이점까지 포기하지 않는다. 예를 들어 분리 포켓은 작은 물건을 한 공간에 섞지 않고 나누어 보관하는 이점, 손잡이는 파우치에 담은 물건을 한 단위로 옮기는 이점으로 연결할 수 있다. 이를 `찾는 시간이 절반`, `분실 방지 보장`, `손목 피로 감소`로 확대하려면 별도 근거가 필요하다. `고객 가치`를 ‘기능을 알 수 있음·주의사항을 확인함’으로만 채우지 말고, 사용에서 무엇이 편해지거나 어떤 경험을 얻는지 적는다. 조건 안내는 그 가치를 보완하는 구매 정보로 분리한다.

근거는 식별자와 위치를 함께 기록한다. 사진이면 파일명과 보이는 부위, 문서면 페이지·항목, 웹이면 실제 확인한 URL과 해당 모델을 적는다.

| 근거 상태 | 사용할 수 있는 범위 | 금지하는 확장 |
|---|---|---|
| 사진에서 관찰 | 패턴·구성·외형, 보이는 사용 방식 | 촉감·혼용률·흡수 속도·내구성·실측치 단정 |
| 사용자 스펙·설명서·공식 자료 | 같은 모델·옵션에 명시된 기능과 조건 | 다른 모델 정보 전용, 제조사 설명을 독립 시험 결과로 승격 |
| 시험·인증 자료 | 대상·조건·범위가 맞는 주장 | 조건 삭제, 수치 확대, 인증 대상 혼동 |
| 기획 가정·연출 | 사용 맥락, 공간 분위기, 취향 제안 | 효능·비교 우위·실제 경험의 증거로 사용 |

중요한 장점을 설명할 근거가 빠졌다면 보유 자료부터 확인한다. 정확한 모델이나 상품 링크가 있고 조회 도구를 쓸 수 있으면 공식 자료를 확인한다. 모델 일치가 불확실하면 비슷한 상품의 스펙을 가져오지 말고 필요한 항목만 묶어 질문한다. 조회 도구가 없거나 근거를 찾지 못하면 그 상태를 기록한다.

확인 대기 중에도 근거가 있는 소구와 장면 기획은 진행한다. 핵심 구매 이유가 미확인 주장에 의존하면 해당 생성은 보류한다. 관찰 가능한 디자인·사용 맥락만으로도 유효한 구성이 가능하면 그 범위를 밝히고 제안한다. 실제 판매에 필요한 정보가 부족한 결과는 시안으로 표시한다.

## 2. 소구 맵

관련성·근거의 강도·다른 소구와의 차이를 기준으로 주 소구 하나와 필요한 보조 소구를 선정한다. 고객이 사야 할 이유를 설명하지 못하는 `고급스러움`, `디테일`, `여유`만으로 소구를 확정하지 않는다.

| ID·우선순위 | 고객의 상황·욕구 | 제품 특징·장점 | 기능적·감성적 고객 가치 | 근거 ID·허용 범위 | 핵심 메시지 | 보여줄 행동·상태 |
|---|---|---|---|---|---|---|
| S1·주 소구 | 작은 물건을 한 칸에 섞어 담고 싶지 않음 | 분리 포켓이 확인됨 | 물건마다 둘 자리를 나누어 보관 | E1: 내부 사진, 수납 치수 미확인 | 작은 물건도 제자리로, 나눠 담는 수납 | 분리된 공간과 각 공간에서 물건을 꺼내는 동작 |

위 예시는 해당 구조가 확인된 가방의 예시다. 소지품 적합성·크기를 확인하지 못하면 특정 기종 수납이나 용량을 단정하지 않는다. `고객 가치`는 스펙을 그대로 반복하는 칸이 아니다. 왜 그 특징을 원하는지 설명한다.

복수 패널은 각 장이 새 구매 정보 또는 구매 장벽 해소를 담당해야 한다. 같은 소구를 다시 다루더라도 상황 제시→사용 방식→근거처럼 답하는 질문이 달라야 한다. 줄무늬·질감·로고를 모두 독립적인 강점으로 부풀리지 않는다.

## 3. 장점과 필요 상황의 시각화

소구마다 먼저 `글자를 가려도 무엇이 달라지는지 보이는가?`를 묻는다. 장점을 이해시키기 위해 필요한 상황·행동·작동 과정·결과 상태를 선택한다. 예쁜 배경이나 효과 자체를 소구의 설명으로 간주하지 않는다.

| 전달할 내용 | 적합한 시각화 | 사실 경계 |
|---|---|---|
| 왜 필요한가 | 구체적인 사용 순간, 손의 동선, 공간의 제약 | 과장된 불편, 조작된 경쟁 제품 실패 금지 |
| 사용이 어떻게 달라지는가 | 제품을 실제로 잡고 쓰는 행동, 순서, 보관 상태 | 확인된 사용 방식·크기·호환성 안에서 연출 |
| 구조·표면의 장점 | 해당 부위 접사, 열린 상태, 검증된 구조 설명 | 표면 사진으로 내부 단면·소재 성능 추측 금지 |
| 보이지 않는 기능 | 확인된 기능에 한해 흐름선·열·수분 등의 개념 표현 | 필요하면 `이해를 돕기 위한 연출` 표시, 실제 시험·측정처럼 표현 금지 |
| 취향·공간 분위기 | 같은 제품을 다른 공간·스타일링에서 보여주기 | 감성 제안을 객관적 성능으로 바꾸지 않음 |
| 비교·전후 | 비교 조건과 근거가 확보된 경우의 설명 | 생성된 사진 자체는 효과·실험 증거가 아님 |

시각적 은유도 기능 주장이다. `연출`이라는 주석만으로 미확인 보온·흡수·냉각 기능을 넣지 않는다. 제품이 닿기만 해도 물기가 사라지거나 피부가 변하는 표현은 문구가 없어도 결과를 주장한다.

모든 제품에 단면·화살표·전후 비교가 필요한 것은 아니다. 사용 장면으로 충분하면 그 장면을 고른다. 기능 근거가 부족해도 디자인 조화·배치·관찰 가능한 사용 방식은 새 장면으로 설득할 수 있다.

제품 사진만으로 차단·흐름·재질·접촉 부위·내부 구조가 보이지 않아 구매 가치가 약해지면 [CG 시각화 판단 카탈로그](cg-visualization-catalog.md)를 함께 읽고 CG 후보를 만든다. 연출컷도 이 판단을 거치며, CG는 효과를 꾸미는 장식이 아니라 확인된 개념의 위치·범위·방향·구조를 보여주는 한 장면이다. 근거가 없으면 표현을 관심 부위·표면 관찰·실제 사용 동작으로 낮춘다.

## 4. 장면 설계표

| 장면 ID·패널 | 소구 ID·구매 질문 | 시각화 방식·보이는 행동/결과 | 공간·구도·거리 | 제품 참조·잠금 요소 | 기존 컷과 달라지는 구매 정보 |
|---|---|---|---|---|---|
| V1·01 | S1·어떤 상황에 필요한가 | 출근 직전 포켓에서 소지품을 꺼내는 손 | 현관, 허리 높이 중경 | E1 내부·E2 외관, 지퍼·포켓 위치 유지 | 제품이 쓰이는 순간 |
| V2·03 | S1·어떻게 구분해 담는가 | 확인된 포켓 구성을 보여주는 열린 상태 | 탁자, 위에서 본 근경 | E1, 보이지 않는 칸 추가 금지 | 구분 수납의 구조 |

제품 정체성은 고정하고, 판매 메시지에 필요한 배경·행동·구도는 새로 설계한다. 원본 모델의 포즈나 카메라까지 자동으로 잠그지 않는다. 알 수 없는 면은 보여주지 않는 구도를 선택하거나 추가 참조를 받는다.

상세페이지·다장 세트는 기본적으로 제품 중심 컷, 사용·필요 상황, 장점·구조 설명 등 서로 다른 장면 역할을 배치한다. 상세페이지 안의 연출·효용 시각화는 상세페이지 제작에 포함되며, 별도 분기나 전체 패키지를 선택해야만 만드는 것이 아니다.

같은 사진의 크롭·반전·색감·문구 변경이나 사실상 같은 포즈의 재생성은 새 연출로 세지 않는다. 배경만 바뀌어도 새로운 사용 맥락을 전달하지 못하면 반복이다. 접사는 전에는 보이지 않던 유효한 디테일을 설명할 때 독립적인 역할이 있다.

동일한 장면을 여러 패널의 주 이미지로 반복하지 않는다. FAQ·마무리에는 제품 사진을 억지로 채우지 않아도 된다. 사용자가 원본만 사용하거나 같은 구도를 반복하라고 지정했다면 그 범위에서 정보 차이를 만들고 장면 다양성의 예외를 기록한다. 새 장면을 만들었다고 보고하지 않는다.

## 5. 제작 진입과 결과 기록

카피 확정 전에 소구 맵과 장면 설계표를 연결한다. 상세페이지 구성 승인에는 핵심 소구, 허용 근거, 각 장이 추가하는 정보와 시각화 방식을 포함한다. 기존 승인 범위 안의 보완에 승인을 반복 요구하지 않는다.

주 소구에 근거가 없거나, 장점 설명 패널의 시각화가 장점을 보여주지 못하거나, 원본 반복으로 장수를 채우면 기획 단계에서 수정한다. 승인 자체는 이 결함을 통과시키지 않는다.

작업 기록에는 `소구 맵 → 장면 설계 → 패널 프롬프트 → 실제 결과·검수`를 같은 ID로 연결해 남긴다. 파일 저장이 가능한 다장 작업이면 브리프·패널 목록·검수 기록으로 보관하고, 그렇지 않으면 대화에 간단한 표로 남긴다. 사용자에게 내부 표를 매번 길게 읽히거나 별도 도구 설치를 요구하지 않는다. 이 문서는 에이전트가 실행할 기준이며 자동 평가기나 매출 상승 보장이 아니다.
