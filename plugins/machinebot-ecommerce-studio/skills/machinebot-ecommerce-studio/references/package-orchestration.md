# 전체 이미지 패키지 연결

전체 패키지는 별도 생성 스킬이 아니라 승인된 제작 스킬의 결과를 조합하는 결과물 분기다. [제품 기록](product-context.md)의 `plans`에 package plan을 만들고, 슬롯마다 독립 스킬의 `asset_id`를 연결한다. 직접 요청된 자산은 pass이고 원본·옵션·소구 연결이 맞을 때 재사용한다.

## 라이트 기본 슬롯

- cutout 1~2개
- thumbnail 6개
- lifestyle 4개
- benefit 3개
- detail 6개

풀 패키지는 `branches.md`의 수량을 사용한다. 라이트/풀 선택과 패키지 구성안은 한 번 승인받는다. 테스트 제품은 `mode=synthetic`을 끝까지 유지한다.

## 실행·재개

1. 제품 옵션·원본 해시·사실 경계를 확인한다.
2. 승인된 plan의 실제 슬롯과 기존 pass 자산을 읽는다. failed/unreviewed/stale, 다른 variant, 다른 source hash는 슬롯을 충족하지 못한다.
3. 누끼 → 연출 → 효용 → 썸네일 → 상세 순서로 필요한 미완료 슬롯을 각 독립 스킬에 보낸다. 상세페이지가 먼저 승인된 경우에는 독립 누끼·연출을 강제로 만들지 않는 예외를 유지한다.
4. 같은 파일을 두 슬롯에 세지 않고, 재사용 파일은 manifest에 표시한다. 새 호출은 새 자산 ID로 기록한다.
5. 모든 슬롯이 pass이고 실제 파일·검수·source hash가 닫히면 manifest·연결본·ZIP을 만들고 전체를 다시 연다. 하나라도 실패·미검증이면 부분 manifest만 만들고 `complete`로 표시하지 않는다.

원본·옵션·사실 변경은 영향 자산을 stale로 만들고 해당 분기부터 재개한다. 같은 문제가 두 번 반복되면 무한 재시도하지 않고 원인·대안을 사용자에게 제시한다. 읽기 전용 구조 검사는 `scripts/validate_package.py`다.
