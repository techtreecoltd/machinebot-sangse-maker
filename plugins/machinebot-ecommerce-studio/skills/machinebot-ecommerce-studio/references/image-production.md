# 커머스 이미지 생성·편집 제작법

호스트가 제공하는 이미지 생성 기능을 사용한다. 별도의 API 키나 외부 설치가 필요한 경로를 임의로 만들지 않는다. 범용 포스터·캐릭터·UI 스타일로 확장하지 않고 제품 판매 자산에 필요한 구도와 품질만 다룬다.

## 1. 참조 이미지 역할 지정

새 판매 이미지의 기획에는 [소구 설계와 장점 시각화](sales-visual-strategy.md)의 소구 ID·장면 ID를 먼저 연결한다. 기획에서 선택한 장점·필요 상황을 이미지로 설명하는 것이 생성의 목적이다.

여러 이미지가 있으면 각 입력의 역할을 명시한다.

- `이미지 1 — 제품 기준`: 형상, 비율, 색상, 패키지와 로고를 보존
- `이미지 2 — 스타일 기준`: 배경, 조명, 재질 표현만 참조
- `이미지 3 — 브랜드 기준`: 로고, 컬러, 타이포그래피 사용법을 참조

스타일 이미지를 제품 기준보다 우선하지 않는다. 실제 제품이 있는 경우 제품을 새로 디자인하지 않는다.
제품 참조에서 잠글 요소와 바꿀 장면을 명시한다. 원본 사진의 모델·포즈·배경을 그대로 따르는 것은 사용자가 요구했거나 해당 장면의 역할에 필요한 경우로 한정한다. 승인된 히어로는 팔레트·타이포그래피 참고이며 모든 패널의 구도 참고가 아니다.

## 2. 제품 정체성 잠금

매 생성·편집 프롬프트에 필요한 불변 조건을 반복한다.

- 같은 제품 형상, 치수 비율, 모서리, 손잡이·뚜껑·버튼 위치
- 같은 패키지 색, 로고 위치, 인쇄 영역
- 사용자가 제공한 텍스트 외의 가짜 브랜드·라벨 금지
- 부분 수정에서는 요청한 항목만 변경하고 나머지를 유지
- 신규 장면에서는 제품 자체의 구조·무늬·로고 관계를 유지하면서 배경·행동·카메라를 장면 설계에 맞게 변경

보이지 않는 면이나 내부 구조는 자료가 없으면 생성하지 않는다. 제품 사진의 해상도가 낮아 글자가 불분명하면 그 글자를 추측해 복원하지 않는다.

## 3. 커머스 프롬프트 블록

프롬프트는 아래 순서로 구성한다. 복잡한 제품 렌더는 JSON 같은 슬롯 구조를 써도 좋지만 시각 시스템을 설명하는 용도로만 사용한다.

0. `소구·시각화`: 소구 ID, 구매 질문, 근거 범위, 보여줄 행동·과정·결과 상태, 이전 장면과 다른 정보
1. `캔버스`: 비율, 방향, 여백, 썸네일·상세 패널 역할
2. `제품`: 제품과 보여줄 사용 상황
3. `구도`: 카메라 각도, 제품 크기, 시선 흐름
4. `재질`: 금속, 유리, 패브릭, 식품 표면 등
5. `조명`: 소프트박스, 자연광, 림라이트와 그림자 성질
6. `팔레트`: 배경색, 브랜드색, 금지할 색 캐스트
7. `정확한 문구`: 꼭 이미지에 들어가야 할 짧은 문자열만 따옴표로 지정
8. `불변 조건`: 제품 정체성 잠금
9. `피해야 할 것`: 가짜 로고, 깨진 글자, 플라스틱 CGI, 제품을 가리는 소품 등 3~6개

`고급스럽게`, `예쁘게`, `전문적으로`만 쓰지 말고 소구를 보여줄 구체적 행동·상태와 재질·광원 조건을 지정한다. 장면에 필요한 요소만 사용하고 관련 없는 소품을 채우지 않는다.
FAQ에는 [구매 결정형 FAQ](purchase-decision-faq.md)의 확정 브리프를 사용한다. 질문/답변/조건·정확 문자열·답변 중심 면적·산세리프/브랜드 예외·얇은 구분선·작은 식별 컷을 지시한다. 히어로 구도와 큰 제품 사진을 FAQ에 자동 복제하지 않는다. 텍스트로 구매 판단을 돕는 패널에는 새 사용 장면을 억지로 추가하지 않는다.

새 장면 프롬프트 예시(구조가 확인된 가방):

> S1의 구분 수납을 설명하는 V2 패널이다. 제품 참조의 지퍼·포켓·색상·로고를 유지한다. 배경과 인물 포즈는 참조하지 않는다. 제공된 내부 사진에서 확인되는 열린 포켓을 위에서 촬영해 각각의 공간이 보이게 한다. 소지품은 크기 적합성이 확인된 것만 사용한다. 앞 히어로의 현관 장면을 반복하지 않는다. 제품·장면·아래 허용 카피를 한 장 안에서 함께 렌더링한다.

## 4. 기본 상품 촬영 방향

누끼 또는 스튜디오 제품컷 표현을 선택한 자산에는 다음을 사용한다. 메인 썸네일과 상세페이지 전체에 이 배경을 자동 적용하지 않는다. 썸네일은 [표현 선택](../../machinebot-thumbnail/references/thumbnail-design.md)의 모델·장점·정보성 카피·조합 판단을 먼저 따른다. 여기서 누끼는 투명 배경 추출물이 아니라 흰색 스튜디오 제품 마스터컷을 뜻한다.

- 중성 흰색 또는 매우 옅은 회색 스튜디오 배경
- 누런 캐스트 없는 중성 화이트 밸런스
- 부드러운 확산광, 실제 접지 그림자, 정확한 재질
- 제품이 프레임의 중심이며 충분한 안전 여백 보유
- 과도한 반사, 헤일로, 과포화, 과도한 샤픈 금지

누끼 마스터컷은 정면·3/4·측면·상부 등 자료로 확인 가능한 각도를 여러 장 구성한다. 제품 형상·색상·인쇄는 고정하고, 각도·카메라·배경·조명과 자연스러운 접지 그림자만 바꾼다. 투명 PNG는 사용자가 별도로 요청한 추가 편집으로만 다룬다.

연출컷은 제품·타깃에 맞는 공간과 소품을 쓰되, 제품 인지가 첫 시선에 유지돼야 한다.

## 5. 효용 시각화

먼저 해당 기능의 근거와 허용 범위를 확인한다. 보이지 않는 장점은 다음처럼 표현할 수 있다.

- 열·보온: 절제된 열 그라데이션과 흐름선
- 냉각: 옅은 푸른 입자, 결로, 공기 흐름
- 흡수·수분: 단면 레이어, 방향성 화살표, 전후 상태
- 압력 분산·탄력: 접촉면 등고선, 힘 분산선
- 공기 흐름: 반투명 스트림라인

효과가 실제 측정 데이터가 아니라면 숫자 눈금, 온도값, 퍼센트 개선치를 넣지 않는다. 시각 은유가 제품 자체를 가리거나 변형하지 않게 한다.
기능 자체가 미확인이면 수치를 빼더라도 해당 효과를 쓰지 않는다. 생성된 물기 제거·열 차단·피부 변화는 그 자체로 성능 주장일 수 있다. 효과가 필요한 경우 개념 설명임을 밝히고, 생성 이미지를 실험 증거로 제시하지 않는다.

소구는 효과 없이도 시각화할 수 있다. 필요 상황을 드러내는 공간, 실제 사용 동작, 확인된 수납 구조, 표면 접사 등에서 가장 이해하기 쉬운 방식을 선택한다. 주석·화살표·구조 설명도 해당 패널의 동일 이미지 생성 호출 안에서 렌더링한다.

## 6. 원큐 타이포그래피와 2000px 패널

일반 제작과 외국어 원본 재제작 모두 패널마다 제품·배경·효과·확정 카피를 한 번의 이미지 생성 또는 편집 호출에서 함께 렌더링한다. 호출 결과는 별도 글자 레이어가 없는 최종 평탄화 이미지 한 장이어야 한다.

1. 패널마다 들어갈 출력 언어와 정확한 문자열을 확정한다.
2. 프롬프트에 허용 문자열을 따옴표로 열거하고 `이 문자열 외에는 어떤 글자도 만들지 않는다`고 지정한다.
3. 제품 정체성과 텍스트 안전 여백을 함께 잠근다.
4. 제품·장면·효과·타이포그래피를 같은 호출에서 생성하고 결과 문자열을 한 글자씩 대조한다.
5. 실패한 패널은 전체 패널을 이미지 생성 편집 또는 재생성한다. 재시도에서도 별도 글자 패치를 만들지 않는다.
6. 최종 패널을 1080 × 2160px 이상으로 리사이즈하되 픽셀 내용이나 새 텍스트를 추가하지 않는다.

외국어 상세페이지를 입력으로 받았다면 [외국어 상세페이지 현지화](source-detail-localization.md)를 우선 적용한다. 외국어 원본 위에 한국어를 덮는 방식은 사용하지 않는다.

텍스트 없는 이미지 베이스, 투명 타이포그래피 PNG, 텍스트 패치, HTML·CSS·SVG·캔버스·시스템 폰트 렌더링을 만들거나 합성하지 않는다. 이 금지는 한국어뿐 아니라 모든 출력 언어에 적용한다.

법정 고지·성분표·복잡한 표처럼 한 글자 오류도 허용되지 않는 긴 정보가 있고 이미지 생성 편집이 두 번 실패하면, 문구 축약·페이지 간 정보 재배치·제작 명세만 전달 중 가능한 대안을 사용자에게 선택받는다. 이미지 생성으로 정확성을 확보하지 못한 상태에서는 완성이라고 말하지 않는다.

## 7. 생성 순서

1. 가장 정확한 제품 사진을 정체성 기준으로 고정한다. 필요할 때만 마스터 누끼를 만들고, 상세페이지에서는 실제 납품할 히어로를 스타일 테스트로 사용할 수 있다.
2. 전체 세트의 팔레트·광원·소품 수준을 보여주는 스타일 테스트 1장을 만든다.
3. 승인된 방향으로 역할별 이미지를 한 장씩 또는 작은 묶음으로 생성한다.
4. 상세페이지는 패널별로 제품 비주얼과 확정 카피를 한 번의 호출에서 함께 생성한다.
5. 모든 결과를 열어 확인하고 실패한 자산만 수정한다.
6. 전체 패널을 나란히 열어 장면 역할과 소구 전달을 검수한다. 호출 횟수가 달라도 같은 포즈·장면이면 반복으로 판정한다. 프롬프트의 계획이 아니라 실제 이미지로 판정한다.

파일명 예시:

- `01-main-thumbnail.png`
- `02-angle-detail.png`
- `03-lifestyle-kitchen.png`
- `detail-01-hero.png`
- `detail-08-faq.png`

## 8. 수정 프롬프트

수정은 범위를 좁힌다.

> 이미지 1의 제품 형상, 로고, 라벨, 크기와 위치는 그대로 유지한다. 배경만 중성 흰색 스튜디오로 변경하고 부드러운 접지 그림자를 추가한다. 다른 요소는 바꾸지 않는다.

한 번에 제품, 배경, 카피, 구도, 색상 전체를 다시 설계하지 않는다. 반복 실패 시 원본 해상도, 참조 부족, 도구 한계를 원인별로 설명하고 대안을 제시한다.
