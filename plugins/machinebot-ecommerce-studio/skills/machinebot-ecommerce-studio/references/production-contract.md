# 모든 제작 스킬의 공통 계약

직접 호출과 상위 스킬의 연결 모두 이 계약을 적용한다. 제품 원본·사실·검수 자산을 전달하는 기록은 [product-context.md](product-context.md) 하나다. 별도 서버·모델·API 키·Machine Code 설치를 제품 실행 조건으로 요구하지 않는다.

- 원본을 직접 확인하고 형상·옵션·로고·패키지 문구를 보존한다. 자료 없는 면·부속·구조를 발명하지 않는다. 생성물과 연출은 사실의 증거가 아니다.
- 사진에서 관찰한 외형, 사용자 스펙·공식 근거, 확인 필요, 연출 선택을 분리한다. 효능·수치·인증·리뷰·순위·의학 주장과 시각 효과에 동일한 근거 기준을 적용한다.
- 이미 지정한 타입·수량·원본·승인을 다시 질문하지 않는다. 기존 브리프와 기록을 읽고 해당 작업을 좌우하는 누락만 질문한다. 단독 요청은 그 산출물에서 종료한다.
- 누끼·썸네일·연출·효용의 구체적 요청은 제작 승인이다. 상세페이지·전체 패키지는 구성안을 보여주고 한 번 승인받는다. 승인한 계획의 ID와 근거를 기록한다. 이미 유효한 승인이 있으면 반복하지 않는다. 제품·핵심 주장·수량 변경은 해당 승인 범위를 갱신한다.
- 새 세션에서는 [시작 안내](start-here.md)로 납품 종류와 표현 방식을 구분한다. 메인 한 장도 구매 질문과 자료 역할을 판단하며, 메인=흰 배경·무문자로 축소하지 않는다.
- 단순 누끼·부분 수정을 제외한 판매 기획은 [소구 설계](sales-visual-strategy.md)의 소구·근거·장면 ID를 연결한다. 제품 정체성 잠금은 원본 배경·포즈 반복을 뜻하지 않는다.
- 생성 전에 [image-production.md](image-production.md), 검수 전에 [quality-gates.md](quality-gates.md)를 읽는다. 호스트 이미지 기능으로 자산마다 한 번의 호출에 제품·장면·효과·확정 문구를 함께 렌더링한다. 시도 하나는 평탄화 이미지 한 장이다. 독립 누끼/연출 자산을 최종 패널의 텍스트 없는 베이스로 삼아 별도 글자를 합성하지 않는다.
- 투명 글자 PNG·문구 패치·HTML/CSS/SVG/캔버스/시스템 폰트 합성을 만들지 않는다. 후처리는 비율을 보존하는 리사이즈·파일명·연결·압축이다. 목표 비율과 다르면 제품을 늘이지 말고 호스트 편집으로 프레이밍을 맞춘다.
- 실제 파일을 열어 제품·문구·장면·규격을 확인한다. 프롬프트나 파일 존재만으로 pass를 주지 않는다. 세트 전체의 정보 진전·중복도 검수한다. 같은 문제 두 번은 원인·대안 확인 지점이다.
- 도구 부재는 명세까지만, 열람 불가는 미검증이다. 실패/미검증 자산을 다음 단계의 제품 기준으로 쓰지 않는다. 새로운 원본·옵션·수정 파일은 이전 검수를 무효화한다.
- 가능한 호스트에서는 납품 이미지를 대화에 직접 표시한다. 도구에서 이미 보였다면 중복 첨부는 불필요하다. 미리보기 불가 시 제한을 밝히며 “바로 보여줘”에는 기존 결과를 표시한다.
- 납품은 이미지, 번호·용도·크기 목록, 미해결 사실/검수, 수정 방법(파일 번호 + 바꿀 요소 + 유지할 요소)을 포함한다. 상품 사실이 부족하면 시안으로 명시하고 확인 불가 안내로 소비자용 패널을 채우지 않는다.
