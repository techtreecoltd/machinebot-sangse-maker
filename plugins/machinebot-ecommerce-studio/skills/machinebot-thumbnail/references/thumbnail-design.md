# 썸네일의 구매 질문과 표현 선택

메인 한 장, 서브 한 장, 세트 모두 생성 전에 적용한다. 단순 수정은 기존 선택을 유지한다. [시작 안내](../../machinebot-ecommerce-studio/references/start-here.md)와 [소구 설계](../../machinebot-ecommerce-studio/references/sales-visual-strategy.md)의 근거 범위를 따른다.

## 역할과 자료

메인/서브는 노출 위치와 정보 역할이다. 흰 배경/무문자/모델 금지의 동의어가 아니다. 사용자 지시와 해당 채널·카테고리·위치의 확인된 제한을 적용한다. 규칙 미확인을 텍스트/모델 금지나 등록 가능으로 바꾸지 않는다.

제공 사진을 모두 열어 옵션·사용 장면·표면·주장·디자인의 역할을 기록한다. 첫 사진이 자동 주인공은 아니다. 같은 옵션의 모델 사진은 사용 맥락 후보로 검토한다. 사용·제외 이유를 남기며 원본 카피도 유지/축약/교체/제거 이유를 정한다.

## 구매 질문에서 후보 선택

“이 한 장을 보고 구매자가 무엇을 이해해야 하는가?”를 먼저 정한다. 다음은 선택 후보이며 닫힌 메뉴나 장수 할당이 아니다.

| 표현 | 구매 질문 | 구성과 확인 사항 |
|---|---|---|
| 모델·사용 장면 | 어디에, 어떻게 쓰는가? | 제품과 신체/공간의 관계를 읽히게 한다. 얼굴이 제품을 가리지 않게 크기·접점을 설계한다. |
| 장점 시각화·디테일 | 어떤 특징이 선택 이유인가? | 표면·구조·행동, 필요한 인셋·설명·근거 있는 CG. 숫자 없는 효과도 주장 범위를 지킨다. |
| 스튜디오 제품컷 | 어떤 제품·색상·구성을 받는가? | 흰색 또는 적합한 배경의 선명한 상품컷. 유효한 후보이지만 모든 메인의 자동 기본값은 아니다. |
| 정보성·후킹 카피 | 사진만으로 읽히지 않는 핵심 정보는? | 확인된 특징·사용 맥락을 짧고 구체적인 문구로 강조한다. 큰 글자·숫자도 같은 호출에서 생성한다. 가짜 1위·할인·후기·효능 금지. |
| 조합 | 사용과 선택 이유를 함께 보여줘야 하는가? | 모델+디테일+짧은 카피 등을 한 주 메시지 아래 배치한다. 여러 배지·메시지로 제품을 묻지 않는다. |

표현이 지정됐으면 우선 적용한다. 미지정이면 자료에 맞는 후보를 비교해 선택 이유와 주요 대안의 미선택 이유를 짧게 기록한다. 네 유형을 강제 생성하거나 매번 스타일 선택·승인을 요구하지 않는다.

## 최소 제작 기록

기존 product-context의 plans.scope 또는 프롬프트와 분리한 제작 기록에 다음을 짧게 남긴다. 새 JSON 계약이나 긴 기획서를 강제하지 않고 운영 기록을 이미지 카피로 넣지 않는다.

```text
범위: 메인 1장 / 1:1 / 채널과 이미지 위치
자료: 파일별 역할·옵션·열람 여부 / 실제 입력과 제외 이유
구매 질문·주 소구: 전달할 의미와 근거
표현 선택: 방식·조합 / 대안과 미선택 이유
화면 구조: 주인공·제품 크기·행동/디테일·배경·문구 위계
카피: 정확 문자열 또는 없음과 이유 / 근거와 허용 범위
채널 확인: 안내·날짜·적용 범위 또는 미확인 / 적용 제한
검수: 제품 식별·용도/소구 전달·가독성·원본 보존 / 직접 이미지 표시
```

## 예시와 반례

- 접힌 토퍼+같은 회색 옵션의 모델 사용 사진: 접힌 볼륨만으로 용도가 읽히는지 비교한다. 침대 사용컷을 주 장면으로 삼고 원단 디테일·용도 카피를 조합할 수 있다. 선택 없이 첫 사진 배경만 지우면 판단 누락이다. 모든 토퍼에 같은 레이아웃을 강제하지 않는다.
- “흰 배경, 글자 없이 한 장”: 바로 스튜디오컷으로 진행한다. 모델 사진이 있어도 명시 지시를 덮지 않는다.
- “모델 사진에 이 문구를 크게”: 해당 사진·정확 문구로 한 호출에서 완성한다. 문구는 서브에만 가능하다고 설명하지 않는다. 실제 확인한 채널 제한과 충돌할 때만 조정한다.
- 성능 근거 없는 쿠션: 확인된 접촉 모습·표면은 가능하나 통증 개선·압력 분산 수치는 만들지 않는다. 소재명·치수는 제공 근거 수준을 보존한다.
- 여러 색상 사진: 같은 옵션으로 혼합하지 않는다. 옵션 선택이 미해결이면 그 한 가지만 확인한다.

## 결과 검수

실제 결과를 원본과 비교하고 작은 화면에서도 확인한다. 기획한 제품·용도·선택 이유가 읽히는지, 모델/문구가 제품을 가리지 않는지, 필요한 카피를 임의 제거하지 않았는지 판단한다. 흰 배경·규격만 맞아도 의도한 소구가 보이지 않으면 수정한다. 서브는 새 구매 정보를 더한다. 직접 검수와 전환율 실험을 구분한다.
